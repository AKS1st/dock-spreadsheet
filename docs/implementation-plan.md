# dock-spreadsheet implementation plan

Goal: A standalone, read-only dock-files viewer for XLSX/XLS/ODS/CSV/TSV. Approved in this conversation: SheetJS CE parsing, Tabulator grid, sheet selection, sorting, filtering and searching; implementation adds Papa Parse for delimited text after a regression exposed SheetJS CSV/HTML misdetection; no editing, formula execution, macro execution or source-file writes.

Architecture: dock-files retains file dispatch ownership. New plugin registers one viewer/editor view through `ctx.files`/`ctx.workbench`; Host implements a same-origin, size-limited binary read endpoint; Client parses Excel/ODS with SheetJS and CSV/TSV with Papa Parse as data, then renders text cells in Tabulator. No new dock-files API and no change to its dirty worktree.

Baseline: `plugins/dock-files/src/client/index.ts`, `plugins/dock-images/src/index.ts`, `plugins/dock-images/src/client/index.ts`, `plugins/dock-markdown/tsdown.config.mjs`; SheetJS CE official format/install docs and Tabulator documentation. Change necessity: no existing viewer supports workbook formats or sheet navigation; config-only change cannot deliver this behavior. TDD Route: off / skipped; add focused post-change regression tests and build checks.

Tasks:
1. Scaffold independent plugin manifest, build configuration, type-only dock contract and README; pin official SheetJS CE package and mature Tabulator runtime dependency.
2. Host read endpoint: trust fence, absolute path, extension allowlist, regular-file validation and 20 MiB size ceiling; return binary (not base64 JSON); tests cover path/size/trust and read-only behavior.
3. Client: parse workbook without evaluating formulas, preserve row/column coordinates and blank cells, render Tabulator with virtual scrolling, sheet chooser, column sorting/filter/search, loading/empty/error states; clean up instances on unmount/HMR.
4. Verify install/check/test/build, inspect emitted client bundle for unresolved imports; if feasible run an isolated profile without touching running dsh web. Stage deployment config/link only if authorized and writable; do not restart the active process. Report remaining runtime verification and user-controlled restart.

Outcome (2026-10-01):
- Tasks 1-3 initially delivered with 9 tests; task 4 was subsequently completed through isolated live-browser verification (see below).
- Verification found and fixed two real defects: SheetJS misdetects CSV whose first cell begins with `<` as HTML (delimiter-separated files now parse with Papa Parse), and Tabulator silently drops filters applied before its initialization pass (the search term is now retained and re-applied on `tableBuilt`, gated on the table's own ready state instead of a self-managed flag).
- Runtime DOM verification runs in jsdom with the real `lib/client.js`, React 18 and Tabulator: mount, search, sort and worksheet switching are exercised. `react-dom/client` must be imported only after the jsdom globals exist, otherwise its event system never delivers dispatched events to React — a test-harness constraint, not a product constraint.
- Live Web verification (task 4) completed in the isolated container on harness `639ed0153972`: a real `dsh web` on a random port plus real Chromium passed 15/15 checks — client activation, file-explorer dispatch, viewer mount, host route serving 16977 bytes as `application/octet-stream`, worksheet list, cell text, HTML-as-text, search filtering and worksheet switching. No page errors; the only failed responses were the container's documented `dsh-sysmon` 503s. Evidence: `dsh-verify/reports/dock-spreadsheet-audit.json`, screenshot `dock-spreadsheet-viewer.png`, driver `dsh-verify/scripts/run-dock-spreadsheet-check.sh`.
- That live run also found a small UI defect: Tabulator's per-column header filters are `input[type=search]`, so the toolbar search styling stretched them; the toolbar input now carries `.ds-sheet-search` and the selectors no longer overlap.

Follow-up (2026-10-01): cell URLs are detected and open on Ctrl/⌘+click. Detection covers explicit `http(s)://` and `www.` only (bare domains and e-mail stay text, because tabular data would false-positive), trims sentence punctuation and unbalanced brackets, and preserves the cell text verbatim. Each anchor owns its click listener rather than using Tabulator's column `cellClick`: the runtime only routes that callback through the edit flow, so a read-only grid never receives it. Plain click is swallowed; Ctrl/⌘ opens with `_blank` and `noopener,noreferrer`. Verified by 9 detection tests, the jsdom mount test (anchor text/href, plain click no-op, Ctrl and Cmd open) and the live Chromium run, now 18/18.
Follow-up (2026-10-01, UI polish): User approved a Google Sheets / Excel-like **read-only** shell while retaining Tabulator (rather than CSS-only changes or swapping in an editor engine). The client now displays a file badge and read-only state, search/filter toolbar, coordinate + full plain-text inspector with cell highlight, spreadsheet-like grid, keyboard-operable bottom worksheet tabs, row/column status, and responsive chrome controlled by the viewer's own width. Header filters start collapsed; hiding them clears any column filter so invisible constraints cannot remain. CSS is owned in `src/client/styles.ts`; no parsing, Host, or external contract changed. The existing URL modifier-click and HTML-as-text guarantees remain. Unit/integration: `pnpm run check` and 18/18 tests. Isolated real Web + Chromium: 29/29 checks, including a 360px wide viewer; screenshots: `dsh-verify/reports/dock-spreadsheet-viewer.png` and `dock-spreadsheet-compact.png`. The first column-filter automation failed because Playwright `fill()` emits `input`, whereas Tabulator's header editor listens to `keyup`/`search`; a keyboard-driven browser check passed without product-code change.
- Deployment history: at the initial verification, `/` was read-only and the profile link could not be created; staged manifest changes were reverted. On this UI follow-up, the host Web profile already lists `dock-spreadsheet` and its `node_modules` link resolves to this repository (added outside this task). The current 3080 GUI requires authentication from the browser test session (HTTP 401), so whether it has reloaded this updated bundle is **not verified**. This task did not edit the profile or restart dsh web; the user controls any restart needed to activate updated code.

Compatibility/security: same-origin/loopback-or-trusted-host request fence, no writing endpoints, no arbitrary HTML formatter, direct content text only. Large files fail explicitly. Parsing can remain expensive near the limit; document bounded risk. No old path retired, because this is an additive viewer. Stop if dependencies cannot be acquired or isolated execution cannot verify the integration; do not claim running GUI activation from build success.
